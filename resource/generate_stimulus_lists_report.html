Fundamental definitions — not list constraints

Two meanings of congruency

Let Ct and Ft denote the current center and flanker letters. Previous-trial letters are Ct−1 and Ft−1.

Perceptual congruency

Do the current letters match?

P = (Ft = Ct)

This definition is identical in 0-back and 1-back. It concerns simultaneous visual identity only.

Behavioral congruency

Does irrelevant evidence support the task response?

The relevant behavioral comparison changes with the task. Behavioral congruency therefore has a task-specific derivation even though its final CSV label remains yes or no.

0-back behavioral rule

H versus non-H response mapping

Define R0(X) = (X = H). Behavioral congruency is:

R0(Ct) = R0(Ft)

The center and flanker are behaviorally congruent when both map to YES or both map to NO under the fixed-target rule.

1-back behavioral rule

Match-status compatibility

Define the task match T = (Ct = Ct−1). Behavioral congruency is:

T = P

Ft = Ft−1 can strengthen match evidence in selected conditions, but it is a construction rule rather than the definition of behavioral congruency.

Important: behavioral congruency is derived from task-relevant response compatibility. It is not an independently crossed third factor, and no difficulty category is assigned.

A denotes a correct NO response; B denotes a correct YES response. Suffix 1 is behaviorally congruent and suffix 2 is behaviorally incongruent.

Generation requirements

Actual list constraints

These requirements govern the composition and ordering of generated rows; unlike the preceding construct definitions, they can pass or fail.

  1. Output contract. CSV columns are exactly TrialNumber, CenterLetter, FlankerLetter, PerceptualCongruency, BehavioralCongruency, CorrectResponse, ConditionType. Practice/main contain 20/160 scored trials. Each 1-back file adds response-free trial 0.
  2. Condition composition. Practice contains 5 and main contains 40 of each A1/A2/B1/B2. Consequently, each binary field is exactly 50% yes and 50% no over scored trials.
  3. Main-quarter structure. Trials 1–40, 41–80, 81–120, and 121–160 each contain 8–12 of every condition. Within a ListVersion, 0-back and 1-back share the same main ConditionType order.
  4. Letter-identity runs. Across displayed rows, center and flanker identity runs are capped at 4 and identical center/flanker-pair runs at 3. In 1-back, a run of three consecutive YES responses requires four identical centers.
  5. Congruency sequences. PerceptualCongruency and BehavioralCongruency each have maximum run length 3 across scored trials, including across quarter boundaries.
  6. Response sequence. CorrectResponse independently has maximum run length 3 across scored trials. In every main list, YES and NO have equal exact run-3 counts, with 2–4 per value and fewer than 10 pooled; their exact run-2 counts differ by no more than 5. The two main ListVersions use different run-2 count pairs.
  7. First-order transitions. For every binary field, yes→yes, yes→no, no→yes, and no→no differ by at most 1: sorted counts are [4,5,5,5] in practice and [39,40,40,40] in main.
  8. Letter counts. Identities are balanced as evenly as mathematically possible both within each legally variable condition/position cell and overall. In 0-back, H necessarily occupies 50% of both positions; S/C/F split the remainder. In 1-back main, every condition/position cell contains exactly 10 of each letter.
  9. Distinct versions. Versions differ at ≥50% of scored positions in ConditionType, CorrectResponse, and complete-row content; they are not cyclic rotations, reversed rotations, or repetitions of a shorter divisor-sized motif.

Verification rules

How validation is scoped

Trial 0

Excluded from scored condition counts, quarters, binary runs, transitions, letter quotas, and cross-version comparisons. Included in displayed center/flanker run checks and used as the previous state for 1-back trial 1.

Read-back validation

Every written CSV is reopened and checked against its header, row numbering, logical task rules, derived labels, all sequence/count constraints, and version-level requirements using explicit exceptions.
